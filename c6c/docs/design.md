# c6c 设计

> **状态**：P0（设计定稿待实现） · **索引**：[README](../README.md) · **计划**：[plan.md](plan.md) · **清单**：[todo.md](todo.md)
>
> 一句话：**一次 lowering + 流式 IR + 三个发射器**；不建表达式 AST、不驻留 IR、不做优化器。
> 每条设计决定都在 §0 里对着实测数字，不靠偏好。

## 0. 约束（先给证据，再给设计）

| 约束 | 实测证据 | 设计后果 |
|---|---|---|
| 时间的大头是“读代码”，不是“出码” | tcc 自编译 135 ms：`-E` 109 ms（其中纯词法+打印 61 ms），解析+出码+写 obj 仅 25 ms（0.43 µs/行） | 词法层必须比 tcc 快 5–10×（目标 0.2–0.4 µs/行）；codegen 只要 2–3× 于 tcc 就能封顶总预算 |
| 内存是分水岭 | tcc 230–320 B/行；gcc -O0 2.4 KB/行；uya 11–36 KB/行 | 硬指标 ≤500 B/行 → 禁止驻留 token、禁止表达式 AST |
| 多趟会超线性 | uya 4× 输入 → 10× 时间；tcc 4× → 3.7× | 不允许任何按 token/符号线性扫描套线性扫描的结构；线性度进 CI |
| 语言运行时税会吃掉预算 | `try` 每调用 +27 ns（`__tcc_err_flag_get` 13.5 ns vs 普通调用 2.95 ns） | 错误 ABI v2：错误 id 走出参，TLS 只放消息 |
| 文本后端最贵 | tcc 产 `.c` 569 ms / 26 MB；产 `.ll` 1186 ms / 47 MB（输出 18.9 MB） | 文本直写 fd、批量 memcpy、类型串预格式化；绝不把输出拼在内存里 |
| **编译器自身的 codegen 质量决定它自己的速度** | tcc 自举后二进制 573 ms vs gcc 版 134 ms（**4.3×**）；同一份词法代码 gcc -O2 0.32 µs/行、tcc 编 1.71 µs/行（5.3×） | native 后端必须做线性扫描寄存器分配 + 窥孔；纯栈式出码过不了 G4b |
| G2c：必须能编 tcc | tcc 源码用 84 处 `__attribute__`、29 处 `__asm__` 改名、100 处 `__builtin_*`、12 处 `typeof`、116 处 `long double`、4,711 行系统头 | 必须有完整的 C99+GNU 属性/内建/系统头层（§9），并把 `tcc.c` 当日常语料 |

## 1. 总架构

```
                     ┌───────────────── 每 TU 一次 ─────────────────┐
 source (mmap) ──► 词法+预处理（span token，无 intern）
                     │
                     ├─► 顶层跳读（跳过函数体）→ 声明表（符号/类型/模块）
                     │        └─ 模块接口 .c6i（导入方不重解析源码）
                     │
                     └─► 每函数：token 流 ──► lowering（一次）──► IR 流
                                                  │
                        ┌─────────────────────────┼─────────────────────────┐
                        ▼                         ▼                         ▼
                 x86-64 编码器              C99 打印器                LLVM IR 打印器
                 （即时消费，不驻留）        （直写 fd）                （直写 fd）
                        │                         │                         │
                    .o / 可执行                .c（tcc 也能编）            .ll（clang 编）
```

分工与“不做的事”：

| 层 | 做 | 不做 |
|---|---|---|
| 词法/预处理 | 指令、宏展开（token 区间重放）、`#include_next`、`#if` 算术、`#pragma`、`#line` | 不做字符串 intern、不复制标识符、不预读整个文件 |
| 声明层 | 顶层声明、类型（hash-consing）、模块导入 `.c6i`、函数签名 | 不做跨 TU 分析、不做可达性 |
| lowering | C + c6 语义**一次**降到 IR；需要二次看的用 token 区间重放（≤2 次/函数） | 不建表达式树、不做优化、不做寄存器分配前的 SSA |
| 后端 | 消费 IR 流：编码或打印；ABI 归后端 | 不重复实现 c6 语义（这是现状的毛病：c99 47 处 / llvm 65 处 c6 钩子） |
| 驱动 | 并行模块、增量缓存、链接、`-run`/`-test` | 不 spawn 外部汇编器/预处理器 |

## 2. 词法与预处理层

**数据结构**

```c
/* 20 字节一条（P1 实测定型）。整个 TU 的“流”只有当前窗口 + 重放栈，从不整份驻留 */
typedef struct Tok {
    u32 off;      /* 源码偏移；合成 token 指向合成缓冲 */
    u32 len;
    u32 hash;     /* 扫的时候顺手算好，宏表查表用（省一次重扫） */
    u16 kind;
    u16 file;     /* 源文件 id，行号靠它的行首表二分 */
    u8  flags;    /* SPACE / BOL / SYN */
    u8  pad0;
    u16 pad1;
} Tok;
```

比最初设想的 8 字节多：`hash`（宏表按名字查，展开时每个 token 都要查一次）与
`file`（多文件 include 栈下没它就算不出行号）。多出来的 12 字节不占常驻内存——
token 只活在流式窗口里。

- 源码 `mmap(MAP_PRIVATE)`，标识符就是 `(off,len)`，**零复制、零 intern**；只对“要查表的名字”
  算 FNV-1a-64 后截断到 32 位做键（uya 的坑：饱和乘法会让哈希退化，必须用无符号乘法再截位）。
- 符号表开放寻址、2 的幂桶、装载因子 ≤0.7；桶里存 `(hash, off, len, sym)`。
- 行号：**不逐 token 记**。每个文件建一张“行首偏移”`u32` 数组，诊断时二分查找（4 B/行，
  60k 行 = 240 KB）；这消除了 uya 踩过的 `line_of(pos)` O(n²)。
- 宏：宏体 = 源文件里的 token 区间；展开 = 把区间压进重放栈（参数替换在重放时做），
  不复制 token 文本。c6 的 `expr/stmt/ident/type` 宏与卫生重命名走同一条路。
- 指令：`#include`/`#include_next`/`#define`/`#undef`/`#if`/`#ifdef`/`#elif`/`#else`/`#endif`/
  `#line`/`#pragma`（`once`/`pack`/`GCC diagnostic` 忽略）/`#error`/`#warning`。
- 目标：**≥4 MB/s**（约 0.25 µs/行），tcc 现状 1.9 µs/行。

### 2.1 P1-3b 实测：预处理器的内存账（先量再改）

`c6c --scan tcc.c`（75,377 行 / 380,920 token，带全部系统头）arena 分项：

| 项 | 改前 | 改后 | 手法 |
|---|---|---|---|
| 展开结果 | 18.16 MB | 0 | 单独池 + **按帧 LIFO 回卷**（帧弹出即整段还回去） |
| 指令行 | 3.03 MB | 3.03 MB | 待办：`#if` 求值/指令行改走临时池 |
| 隐藏集 | 2.54 MB | 2.54 MB | 待办：hideset 节点同样可按帧回收 |
| 宏结构 | 1.07 MB | 1.07 MB | 已做 body 缓冲复用（重复 `#define` 不再新吃一份） |
| 宏体 | 0.47 MB | 0.47 MB | 同上 |
| **arena 合计** | **28.48 MB** | **10.10 MB** | 另有 `Src` 帧从 arena 改固定 1024 槽 LIFO 栈（−10 MB RSS） |

进程 RSS 44 MB → 15.4 MB，`-E` 85 ms（tcc 同口径 110 ms / 11.1 MB）。两个结论
写进后续设计：

1. **“流式”不等于“不占内存”**：真正吃内存的是“活得比函数久”的中间产物（展开结果、
   hideset 节点、每帧一个的 `Src`）。凡寿命 = 一个栈帧的，一律用池 + 水位回卷，
   不要进 arena。
2. **重复 `#define` 必须替换而不是追加**：既是语义（C 6.10.3），又是内存
   （头文件被重复包含 13 次时，宏体/宏结构不复用就是十几 MB）。

### 2.2 `-E` 的验收口径：跨编译器闭环，而不是“和 tcc 逐字节同形”

tcc 的 `-E` 会吃掉 `__attribute__`、把 `__STRING(__USER_LABEL_PREFIX__)` 留成字面量，
逐字节对齐既不可能也没价值。P1-3b 定的口径是**语义闭环**：

```
c6c -E ... tcc/tcc.c > pp.c  &&  tcc -c pp.c -o pp.o     # 必须 0 诊断
```

结果：`pp.o` 与 tcc 直编 `tcc.c` 的 `.o` **`.text` 同尺寸 600,037 字节、仅 42 字节不同**
（差异全部来自 `.data.ro` 里 `__FILE__` 的路径拼写），符号表 4,546 项逐项相同。

为此 `-E` 做了**行号保真**：源文件 token 按自己的行号输出，同行内小跳（≤8 行）补空行，
大跳才打 `# 行 "文件"` 标记；宏展开出来的 token 不推进行号。这样 tcc 报错的行号就是
原始文件的行号——G2c 阶段调试“c6c 编 tcc 的 C 源码”时，这是唯一的定位手段。

## 3. 声明层（每 TU 一次）

1. **顶层跳读**：从文件头扫到 EOF，只处理文件作用域声明；函数体、`test` 块、初始化器的
   `{}` 用括号配对整段跳过（不解析）。成本估 0.05–0.1 µs/行（纯 token 循环）。
   收益：修掉 tcc 的“方法/切片/前向类型必须先声明”限制，且给 defer 序言判定提供依据（§6.3）。
2. **符号表**：定长 64 B 条目（名字 span、类型 id、存储类、位置、模块、属性位）。
3. **类型表**：hash-consing，`C6Type { kind, qual, align, size, nkid, a, b, tag, hash, kids[], offs[], bits[] }`
   同构类型共享一个 id → **类型相等就是 id 相等**（tcc 是 `CType` 到处按值复制再逐字段比，
   比较散在 30 处、布局反复算）。两个实现细节是实测逼出来的：
   - **键里必须带 struct 标签序号**：`struct A {int x;}` 与 `struct B {int x;}` 是不同类型
     （C11 6.2.7），只按形状 intern 会把它们并成一个。匿名结构（tag=0）才按形状 intern
     ——复合字面量正需要这个。
   - **记录分块存**（1024 一块）：翻倍扩容要复制，而在 arena 里复制过的旧数组永远收不回来。
     20k 类型试过：分块前 arena 4.20 MB，分块后 2.25 MB（含哈希桶），≈112 B/类型。
4. **模块接口 `.c6i`**（ADR-4）：一个模块的导出声明序列化成扁平缓冲（类型表 + 符号表 +
   枚举/错误码号段 + 导出宏），导入方 `mmap` 后直接建表，**不重解析源码**。
   失效键：`(c6c 版本, 编译标志, 源文件内容 hash, 依赖 .c6i 的 hash)`。
   v1 只导出声明；`inline`/`static` 函数体不导出（导入方需要时回退到源码，文档写明）。
5. **系统头**：`#include` 走的仍是预处理器（glibc 头不能 `.c6i` 化）。P7 可选做“头文件
   token 缓存”（键同上），不进 v1 门槛。

## 4. lowering：token 流 → IR 流

- 表达式**边解析边降 IR**（tcc 是边解析边出机器码，这里只是把“机器码”换成“IR 记录”）；
  没有表达式树，因此没有节点分配、没有二次遍历。
- 需要“二次看”的语义，全部用**同一段 token 区间重放**（uya 单趟原型已验证 6M 行/s）：

| 特性 | 为什么需要二次看 | 做法 | 上限 |
|---|---|---|---|
| 闭包捕获集合 | 体里出现哪些外层变量，要看完才知道 | 先扫 token 区间求捕获，再正式 lower，env 布局按捕获顺序 | 1 次重放 |
| `async` 帧大小 | 帧里要放哪些局部 | 第一遍静默扫描（IR 丢弃）求局部表，第二遍出状态机 | 1 次重放 |
| defer 序言 | 函数有没有清理点，决定了要不要发 16 B 序言 | 顶层跳读后按 token 区间找 `defer/errdefer/err/try/catch` | 0.5 次（只扫 token） |
| 泛型单态化 | 调用点才知道实参 | 模板登记 token 区间，调用点入 worklist，TU 末重放出实例 | 每实例 1 次 |
| 宏 | 参数替换 | 重放栈（不复制 token） | 展开深度上限 |

**规则**：任何函数体最多重放 2 次；超过就报诊断（而不是悄悄变慢）。这条写进 CI（§10）。

**c6 特性 → IR 映射**（细节在实现时逐条补，这里给出形态）：

| 特性 | lower 成什么 |
|---|---|
| `defer` / `errdefer` | 每清理点一条 `call` 序列 + 帧内 `arm` 位图置位；出口按逆序展开成显式 `call`（无运行期派发器） |
| `err()` / `try` / `catch` | 错误 id 走**出参**（§6.1）；消息写 TLS 冷路径；`try` = 一次比较 + 条件跳转 |
| `T[:]` 切片 | 两个值（ptr,len）+ 每个下标一次边界比较 + 陷阱调用；越界走冷路径函数 |
| 元组 | 复用结构体布局；返回走隐藏 sret 或寄存器对（按大小/成员类） |
| 闭包 / 函数字面量 | `{code, env}` 胖值 + TU 末生成代码对象；捕获按值进 env 结构 |
| 泛型 `@` | 单态化：每个实例一份普通函数/结构体，mangle 名 |
| `@T` 托管引用 | 对象头 + 描述符（静态数据）+ 引用计数调用；环检测在声明层做（静态图） |
| `async`/`await`/`co`/`task` | 帧结构 + 状态机（`pc` 分派）+ 每 `await` 一次 park/restore |
| `spawn` | 参数打包 + 跳板函数 + pthread |
| `f"..."` | 逐段 `__c6c_fmt_*` 调用（零分配栈缓冲） |
| `module`/`import` | 符号名带 `mod__` 前缀；导入走 `.c6i` |
| `test "..."` | 注册到测试表；`-test` 模式下不走用户 `main` |
| 方法 / `interface` | 符号名 `Tag_meth`；胖指针 + TU 末静态 vtable |

## 5. IR

**编码**：24 字节定长记录，流式追加。

```c
typedef struct C6Ir {
    u8  op; u8 type; u8 narg; u8 flags;
    u32 dst; u32 a; u32 b; u32 c;   /* vreg / label 编号：32 位 */
    u32 imm;                 /* 常量下标 / 标签 / 偏移 / 符号 id */
} C6Ir;
```

**op 集合（v1 约 40 条）**：`CONST MOV LOAD STORE ADDR LEA ALLOCA COPY`、
`ADD SUB MUL DIV MOD NEG`、`AND OR XOR NOT SHL SHR SAR`、`CMP BR JMP LABEL`、
`CALL CALL_INDIRECT RET ARG`、`SEXT ZEXT TRUNC BITCAST F2I I2F FADD FSUB FMUL FDIV FNEG`、
`MEMCPY MEMSET`、`TRAP`。c6 语义不留专用 op（都 lower 成上面的组合 + 运行时调用）。

**编码是显式的、不是 struct 直投**：字段逐个按小端写出（`ir_encode`/`ir_decode`）。
理由三条：三后端必须吃**同一串字节**（差分与 fixpoint 才有意义），字节布局不能随
主机 struct 对齐/填充变；逐字节自举比对要对 IR 直接取哈希；编解码能脱离前端自测。
构建器每条记录立刻交给 sink（dump / 计数器 / 后端编码器），IR 不驻留——
`IrBuilder` 里只有 sink 指针、条数和 FNV-1a-64 指纹。

**流式接口**：

```c
typedef struct C6Emitter {
    void (*op)(void *be, const C6Ir *ir);      /* 立即消费 */
    void (*label)(void *be, u32 id);
    void (*func_begin)(void *be, u32 sym, u32 frame);
    void (*func_end)(void *be, u32 sym);
    void (*finish)(void *be);
} C6Emitter;
```

- native：`op()` 直接编码进 section 缓冲，**IR 不驻留**（0 额外内存）。
- c99 / llvm：`op()` 打印到 1 MB 输出缓冲，满即 `write(2)`，**文本不驻留**。
- 回填：标签/跳转用 fixup 数组（`u32` 位置 + 目标），函数结束时一次回填；不做“保留末尾区域”。
- `--emit-ir` 只给测试用（文本形态，顺序稳定），用来做三后端差分。
- 预算：约 3 条/行 × 16 B = **48 B/行**（60k 行 ≈ 2.9 MB；仅 dump 时驻留）。

## 6. 运行时与 ABI

### 6.1 错误槽 ABI v2（ADR-3，实测驱动）

现状：`try f()` 每次调用两次 TLS 访问（clear + peek），`__tcc_err_*` 每次走
`pthread_once` + `pthread_getspecific`，实测 **+27 ns/调用**；自举规模下 200 万次 = 54 ms ≈ 40% 预算。

v2 定义：

```
/* 内部/同 TU 与跨模块统一用出参，最可移植，三个后端同一套 */
T  f(args..., int *err);      /* *err == 0 表示成功；失败时值无意义 */
```

- `try f(...)` → `if (unlikely(*err)) goto propagate;`（一条比较 + 分支，1–2 cycle）。
- 跨 ABI 边界的公开函数（导出的 C 符号）不带隐藏参数：用 `__c6c_err_slot()` 取一个
  **每线程的槽指针**（TLS 访问让调用者自己做一次并缓存在局部），签名保持纯 C。
- 错误**消息**永远只在冷路径（`err()` 真的发生时）进 TLS；成功路径不碰 TLS。
- 目标：≤5 ns/检查调用，典型 1 ns。

### 6.2 运行时单一定义源

`c6c/runtime/rt.def` 用一行一个条目描述所有运行时入口：

```
entry __c6c_gc_new   ptr  (i64 size, i64 align, ptr desc, i32 flags)
entry __c6c_fmt_i    void (i64 v, i32 spec)
...
```

从它生成三份：native 的符号表、C99 头 + `c99-rt` 声明、LLVM 的签名表（现状 llvm-gen.c 里
那张 62 条的硬编码表就是这么来的，只是手工维护）。运行时本体用 c6 写（独立实现，
不复制 `libtcc1.c`），freestanding 变体在 P7 之后再说。

### 6.3 defer 序言消除

tcc 每个 c6 函数都付 16 B 帧 + 4 条清零（单趟编译在序言处不知道后面有没有清理点）。
c6c 有顶层跳读 + token 区间扫描，可以**精确**判定：只在真有 `defer/errdefer/err/try/catch`
的函数里发序言。成本 ~0.05 µs/行，收益是每个小函数少 16 B 帧 + 4 条指令
（自举时几千个函数 → 几十 KB 栈 + 几万条指令）。

### 6.4 聚合按值传参：本地约定（不是 SysV）

SysV 的聚合传参要按 8 字节分块拆进 6 个整数寄存器、超过 16 字节改走栈，
IR 里就得有"一个实参占多个参数槽 + 栈区间"的概念——这是 P2 的活儿。
在自举还没有打通之前，先用一个**本地约定**把语义跑对：

```
调用方：聚合实参 → 拷进调用者自己的临时帧槽 → 只把**地址**当一个 8 字节实参传
被调方：形参是聚合 → 在入口把指针指向的对象整块拷进自己的局部对象槽
```

- 语义等价（按值传递：被调方改不到调用方的对象），且只用到既有的"一个实参一个
  8 字节槽"的 IR，不必扩 IR、不必拆寄存器。
- 代价是一次多余的拷贝（≤ 结构体大小），在自举这种规模下可以忽略。
- **限制（记在这里，别踩）**：只对 c6c 自己编译的代码成立。把聚合按值传给
  外部（libc/别的编译器产出的 .o）会走错 ABI；聚合**返回**目前是"把被调方
  帧里的地址传出来"，调用方必须在被调方返回后立刻用掉（赋值/传参都行，但
  不能跨调用存着）。要接外部代码，必须补 §6.4 的真 SysV 分块（P4 一起做）。

### 6.5 类型提升与比较：两处曾经静默错的地方

1. **条件码的有符号性**：`u64 0xcbf2... <= 0xFFFFFFFF` 曾有恒真的 bug——`jle`
   把 `0xcbf2...` 当负数。规则：公共类型无符号（含指针）就用 `ULT/ULE/UGT/UGE`，
   有符号才用 `LT/LE/GT/GE`。
2. **操作数归一化**：比较前两个操作数都要按公共类型重扩一次（`IR_TRUNC` 到窄
   类型会按目标类型零/符号扩展）。少了这步，`(int)-1 == 0xFFFFFFFFu` 会在槽里
   变成 `0xFFFFFFFFFFFFFFFF` vs `0x00000000FFFFFFFF`，判不等。
   公共类型的选择规则就是 C 的："取宽的；同宽时无符号胜出"。

## 7. 三个后端

共同契约：只实现 §5 的 `C6Emitter` + ABI 表；**c6 语义一律不在这里**。

| 后端 | 策略 | 代码量目标 | 关键约束 |
|---|---|---|---|
| **x86-64 native** | IR 流上做**线性扫描寄存器分配**（值在寄存器里流动，压力大才落帧槽）+ 函数内窥孔（store-load 合并、常量折叠、比较+分支合并、跳转串接） | 2.5–4k 行 | obj ≤1.2× tcc；**stage2 速度 ≤ tcc 的 stage2**；栈帧 16 对齐 |
| **C99** | IR → C 表达式序列；私有前缀 `__c6c_`；不用 GNU 扩展、不用语句表达式 | 1.2–2k 行 | **生成物必须能被 tcc 编过**（`c99selfhost-tcc` 的隐含约束）；变参走 `rt.def` 生成的 `va_list` 助手 |
| **LLVM IR** | 全 alloca 型（每个 vreg 一个 `alloca`），无 SSA、无 `phi`；帧指针 `%frmp` | 1.5–2.5k 行 | 指针宽度随 triple；符号延迟解析；数据段按长零段切分（现状已有的两个坑） |

**已落地（P3-2a/P3-3a）**：`src/sym.c6`（链式哈希 + 每作用域一条链表，出作用域立刻摘链）、
`src/parse.c6`（递归下降，边解析边发 IR，无 AST）。当前能编：函数定义/原型、递归、
形参（SysV 前 6 个整数寄存器）、标量局部变量、完整运算符优先级链、`&&`/`||` 短路、
`?:`、复合赋值、`++/--` 后缀、`if/else/while/for/do/break/continue/return`。
`make c6c-ctest` 用 gcc 当 oracle 比对 14 个用例的退出码。

### 「0 是合法值」这一课（同一个坑踩了三次）

c6c 里凡是拿 `0` 当「没定义／不存在」的哨兵，都出过错，而且都是**运行时才现形**：

1. **标签偏移**：`lbl[id] != 0` 判「已定义」——第一个函数体的偏移正好是 0。改成按函数换代
   （`lbl_gen[id] == cur_gen`）。
2. **符号偏移**：`if (sym[i].off)` 判「已定义」——第一个函数同样在 0。加了显式 `defined` 位。
3. **类型 id**：`if (!base)` 判「没有类型」——第一个被 intern 的类型（`char`）拿到的正是 id 0，
   于是 `char *msg` 的 `char` 被当成「没有类型」，回落到 `int`：`msg[1]` 按 4 字节步长取址、
   按 int 读，程序返回 0。修法：`tt_init` 里先 intern 一个哑类型占住 id 0，真类型从 1 开始。
4. **虚拟寄存器号**：`if (o.dst)` 判「没有目标」——`return f();` 的调用结果正好落在 vreg 0，
   返回值被丢掉。改成无条件写回。

教训：**流水线里的编号一律从 1 开始，或者另带一个显式的「有效」标志**；
「0 号对象」在单趟编译器里太容易出现了（第一个函数、第一个标签、第一个类型、第一条指令）。

### 写这一段踩到的四个坑（都是“看起来对、跑起来不对”的典型）：

1. **`jcc` 与 `setcc` 的条件码表不一样**：`setcc` 是 `0F 9x`（x=cond），
   `jcc rel32` 是 `0F 8x`（8x = 0x80+cond）。照抄 `0F 84` 给 `jne` 会编出 `0F 05`（syscall），
   程序直接 SIGILL。
2. **标签表要按函数换代**：`lbl[id]` 用 0 当“未定义”哨兵是错的（第一个函数体正好在偏移 0），
   用 “0 也有效” 又要每函数清 16 KB。最后用 `lbl_gen[id] == cur_gen` 判有效。
3. **`while` 的标签必须发在条件求值之前**：条件本身会产生 `cmp/setcc`，标签放在后面会让
   回边跳过条件，变成死循环（C 源码看起来完全正常）。
4. **`for` 的源码顺序与 IR 顺序相反**：源码是 `init; cond; incr; body`，IR 里 body 要在
   incr 之前执行，所以先发 `jmp lcont`，把 incr 放在跳转之后、body 之前——token 只读一遍，
   不能“回头再读”。

**已落地（P2-2a）**：`src/elf.c6` 写单段（RWX）ELF64 + `src/x64.c6` 的编码器，
`_start` 自己用 `syscall 60` 退出、不链 libc。第一个可执行文件 171 字节：
`c6c --hello out` 发 `main(){return 42}`，`make c6c-hello` 断言退出码 42。
当前 vreg 一律落帧槽（**脚手架**，就是为了先打通链路），换成线性扫描是 P2-2b。

**为什么必须做寄存器分配（实测 2026-11-13）**：拿 gcc 编的 `tcc/c6` 把 `tcc.c` 编一遍得到
tcc 的 stage1，再让它编同一个 `tcc.c`：

| 二进制 | 编译 tcc.c | 峰值 RSS |
|---|---|---|
| gcc 编的 `tcc/c6` | **134 ms** | 12 MB |
| tcc 自己编的 tcc（stage1） | **573 ms** | 13 MB |

**4.3×**。tcc 是纯栈式出码（`vstack` + 每个中间值落栈），自举之后自己慢 4.3 倍。
c6c 的目标是“脱离 tcc 且比 tcc 快”，跑的是 **stage2**（c6c 编出的 c6c），所以 §7 的
后端不能是纯栈式：线性扫描 + 窥孔是硬需求。P1 的词法原型给的是同一个信号——同一份
词法代码，gcc -O2 编出来 0.32 µs/行（90.9 MB/s），tcc 编出来 1.71 µs/行（5.3×）。

**ABI 表**（三个后端共用一份声明，后端各自实现）：整数参数寄存器顺序、浮点参数、
`long double`（x86-64 是 80 位 / 16 B 槽）、结构体按值传参（≤16 B 且全整型走寄存器，
其余隐藏指针）、sret、变参（寄存器保存区、`va_list` 布局）、返回多个值（元组 → 结构体）。

## 8. C 方言层（G2c 的硬需求）

c6c 必须编 tcc，所以下面这些不是“加分项”，是 P3 的验收项（清单来自实测，见 plan.md §3.1）：

- **属性**：`alias weak constructor destructor cleanup aligned unused noreturn regparm mode packed section format`；
  未知属性必须**忽略而不是报错**（glibc 头里什么都有）。
- **声明上的 `__asm__` 改名**：`int f(int) __asm__("real_f");` → 符号表用 `real_f`。
- **内建**：`va_list/va_start/va_arg/va_copy`、`frame_address`、`constant_p`、
  `types_compatible_p`、`offsetof`、`expect`、`ffs`、`memcmp/memset/memcpy`、`alloca`、
  `abort`/`trap`；未知内建 → 报错（不能静默）。
- **其它**：`typeof`、`__extension__`、`restrict`、`inline`、`long double`、位域、
  匿名 struct/union、复合字面量、指定初始化器、`__attribute__((cleanup))`（作用域清理）。
- **系统头**：`stdio stdlib string unistd dlfcn pthread sys/mman fcntl setjmp stdarg ctype time`
  共约 4,711 行，必须零报错、零警告地过（`-fsyntax-only` 门槛）。
- **预处理器**：`#if` 的 64 位算术与 `defined`、`#include_next`（按需）、`#pragma` 忽略、
  `#line`、`__DATE__/__TIME__/__FILE__/__LINE__`、变参宏 `__VA_ARGS__`、`##`/`#`。

## 9. 内存模型与预算

- **arena**：每 worker 一个 arena，64 KiB 块链；阶段结束整段释放（永不 `free` 单条）；
  块头 `{ next, used, cap }`。对象按 8 字节对齐，超 4 KiB 的走单独块。
- **生命周期**：词法层借用 mmap；声明表/类型表活到 TU 结束；IR 流只在函数内；
  输出 section 活到写盘。
- **预算**（60k 行、单线程、native）：

| 项 | 预算 | 说明 |
|---|---|---|
| 源码 mmap | 2.5 MB | 常驻页，跨 worker 共享 |
| 行号表 | 0.24 MB | 4 B/行 |
| 符号表 | 1.5 MB | ~15k 条 × 64 B + 桶 |
| 类型表 | 0.5 MB | hash-consing |
| 模块接口 | 0.5 MB/模块 | `.c6i` mmap |
| IR 缓冲 | 64 KiB/worker | 流式 |
| 输出 section | 2 MB | 代码 + 数据 + 重定位 |
| 文本输出缓冲 | 1 MB | c99/llvm 才用 |
| 编译器自身 + libc | 4 MB | 静态数据 + 堆 |
| **合计** | **≈12.5 MB（≈210 B/行）** | 门槛 ≤32 MB |

**五个陷阱（CI 断言“不出现”）**：① token 全量驻留；② 标识符字符串复制/intern 表；
③ 每节点一次 `malloc`；④ 错误恢复保留 AST；⑤ 文本输出拼在内存里（现状 `.ll` 47 MB = 2.5× 输出体积）。

## 10. 并行、确定性与增量

- **并行**：模块 = TU；`import` 给出 DAG；一个进程内 N 个 worker（共享 mmap，独立 arena），
  每个 worker 产出自己的 `.o` 片段 + `.c6i`，按**模块序号**合并 → 结果与串行逐字节相同。
- **确定性**（fixpoint 的前提）：禁止任何“按哈希桶顺序”的输出；符号地址在写盘时定；
  匿名符号（字符串字面量）按“首次出现顺序”分配；并行只改变完成顺序，不改变输出顺序。
- **增量**：缓存键 = `(c6c 版本, flags, 源 hash, 依赖 .c6i hash)`；命中直接复用 `.o`。
  第二次自举目标 ≤10 ms（tcc 无增量，这是项目级超车的主要来源）。
- **线性度**：CI 用 n/4n 合成语料断言**每行成本**增长 ≤1.3×（4× 输入时时间、内存都 ≤5.2×）；
  线性是 4.0×，tcc 实测 3.76–4.21×（≈1.0×/行），uya 10×（2.5×/行）就是这里的反例。

## 11. 引导链与隔离

```
tcc/c6 ──► c6c stage1 ──► (stage1 编 c6c) ──► c6c stage2
             │                                      │
             └── 逐字节比对 stage1/stage2 的 .o ─────┘   ← make c6c-selfhost
```

- **C6-BOOT 子集**：P4 只允许 c6c 自己的源码使用 `defer/err/try/module/import/方法/切片/元组`

- **隔离**（ADR-1）：`c6c/` 不 `#include` `tcc/*.h`、不链接 `libtcc`、不复制 `tcc/` 源码；

- `tcc/` 保留两个角色：bootstrap 第一步、差分测试 oracle；不做运行时依赖。

## 14. 类型表里那些"没有地方放"的位（实现约定）

c6c 的类型是 hash-consed 的 `C6Type`，成员信息压在一个 `u32 bits[]` 数组里。
限定符、位域宽度、成员级 `aligned(N)`、无名标记这几件事**都要挤在这一个
`u32` 里**，所以各段的分配是硬约定，改之前先看这张表：

| 位 | 含义 | 谁写 |
|---|---|---|
| 0..7 | 位域宽度（1..64） | 解析器（`bits[n] = w`） |
| 8..12 | 存储单元内的位偏移（0..63） | `agg_layout` 回写 |
| 13 | **无名位域**（`unsigned : 32;` / 对齐用的 `:0`） | 解析器 |
| 14..29 | 成员级 `__attribute__((aligned(N)))`，存 `log2(N)+1`（0 = 没写） | 解析器 |
| 30 | 枚举位域（按零扩展，tcc 的口径） | 解析器 |
| 31 | **这是位域**（不带这一位就是普通成员） | 解析器 |

两条踩过的坑：

1. `ty_member_bits()` 返回的是**剥掉所有标记位之后的宽度**，所以"这个成员
   是不是位域"**不能**拿它的返回值去和 `0x80000000` 比（恒假）。要问就问
   `ty_member_is_bf()`（看 bit 31）。
2. 无名位域在 C 里**不抬结构体的对齐**，也不占初始化器的位置
   （`{int a; unsigned :32; int b; unsigned long long :64; int c;}`
   是 28 字节、对齐 4，`{1,2,3}` 填的是 a/b/c）。gcc 和 tcc 都是这个口径。
   自测（`--type-selftest`）里造类型也必须按这张表写 `bits[]`，不然
   `agg_layout` 会把位域当普通成员排。

### 14.1 线程局部量（`__thread`）

镜像里照普通全局量放一份，另外导出一个 `(起始偏移, 大小)` 的描述表；
运行期第一条语句之前 `c6c_tls_setup()` 用 `mmap` 出一份**每线程的副本**、
把镜像拷过去，再 `arch_prctl(ARCH_SET_FS, 基址)`。之后 `&tls_var` 一律是
`__c6_fsbase() + goff`（`__c6_fsbase` 是 `asmblob` 里 11 字节的手写机器码：
`mov %fs:0, %rax; ret`）。构造函数里也要先跑一遍 setup——构造函数可能在
`main` 的 TLS 初始化之前就碰 TLS 变量。

### 14.2 原子操作

`_Atomic` 和 `__atomic_*` **不进前端**：`include/stdatomic.h` 把
`atomic_load/store/fetch_add/compare_exchange` 这些宏翻成对运行期
`__c6_at_rmw/__c6_at_xchg/__c6_at_cas` 的调用，运行期用一个 test-and-test-and-set
自旋锁实现；只有 `atomic_flag_test_and_set/clear` 走硬件 `xchg`（自旋锁本身
不能用自旋锁实现，会饿死）。这样三个后端不需要各自的原子指令发射，代价是
"真并发"场景要加锁——够 C 程序用，也不违反 C11 语义。

## 15 内联汇编：`asmx`（native 后端）

自举链上不许依赖外部 `as`/`gcc`，而 C 程序里 `asm` 的用法是**开放**的——没
办法像 IR 那样穷举。所以这里的定位是"翻得动就翻，翻不动就整段静默跳过"，
绝不因为一句不认识的汇编把本来能编过的翻译单元变成编不过（tcc 的
`99_fastcall` 就是 i386 汇编，我们跳过它、让用例按上游自己的 SKIP 处理）。

三段流水：

```
asmx_piece(文本)  → 字节 + 外部重定位项 + 段内标签表
asmx_flush(段)    → 字节放进代码镜像、登记标签符号、落重定位
```

**两条容易踩的线**：

1. 外部重定位记的是**相对本段起点**的偏移。段的落点要等 flush 才知道（前面
   还有别的函数的代码），所以翻译期不能把绝对偏移写死。
2. 段内自己的标号（`1:`、`.Lx:`、`vide:`）在**翻译期**就地回填——它们和引用
   同处一段，段整体搬走时相对距离不变。

**载体**：函数内的 `asm` 在 IR 里只多一条 `IR_COMMENT | AX_MARK|idx`。不新增
op 种类的好处是 C99/LLVM 后端一行都不用改（它们本来就把 `IR_COMMENT` 原样
打印成注释），坏处是"函数内汇编"只有 native 后端有效——这符合预期：asm 本来
就是后端相关的。

**REX 必须发在 opcode 之前**。写错过一次：`cmp $0,%r11d` 编成
`83 41 fb 00`，那是 `cmp [rcx-5],0`——asm goto 一跑就段错误，而且看不出是
汇编器的问题。

## 16 镜像、回填与落盘

native 后端的内存模型：一个 `Image`（`u8 *p / u32 n / u32 cap`），1.5 倍增长。
第 194 轮把它拆成了三段视角：

```
CODE_IMG  代码段（就地在里面回填重定位）
DATA_IMG  数据段（字符串、全局、跳板、TLS 副本）
最终文件 = [ELF 头 120 字节][数据段][代码段]
```

`elf_write_parts()` 按这三段**直接写文件**，不再把 data+code 拼成一份 10.66 MB
的第二镜像；`X64State.im_base` 记住"代码段在镜像里的起点"（单镜像模式下是 0，
老路径行为不变），`x64_resolve` 用 `patch + 4 + im_base` 算相对位移。

**为什么值得**：收尾时那份第二镜像要 `calloc` 10.66 MB，加上原有的
`CODE_IMG`/`DATA_IMG`，峰值就到 37.6 MB。拆掉之后峰值退回到"解析结束时"
的 21.9 MB，收尾不再涨。

还有一处更隐蔽的浪费：asmblob 的跳板是**回填阶段**才追加的，自编译时一共
144 字节，却落在那份 10.66 MB 镜像的尾巴上 → 触发 `img_grow` 的 1.5 倍增长
→ cap 涨到 16 MB 并 `memset` 5.3 MB。**144 字节换来 5.2 MB 峰值**。改成
`img_slack(&CODE_IMG, 64K)` 按需留确定余量、只清真正会用到的页。

跳板的 8 字节对齐要对齐**镜像坐标**而不是段内坐标，否则落点会跟着数据段长度
漂移，两个编译器编同一份源码就不再逐字节相同（fixpoint 会挂）。
