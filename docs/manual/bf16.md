# bfloat16：原生 `bf16` 标量类型

> **状态**：现行规范（`C6_EXT` + `.c6` 后缀） · **索引**：[文档索引](../README.md) · **实现状态**：[status.md](../history/status.md)
>
> `bf16` 是 2 字节的 bfloat16 存储类型：内存里只占 16 位，表达式里按 `float` 参与
> 运算，写回内存时按 round-to-nearest-even 舍到高 16 位（和 torch / LLVM 的
> bfloat16 同口径）。
>
> 相关：用例 `c6c/tests/bf16_main.c6`、验收脚本 `c6c/tests/bf16-check.sh`；
> 语法 [reference/grammar.md §3.12](../reference/grammar.md)

---

## 是什么

`bf16` 取 `float` 的高 16 位：1 位符号 + 8 位指数（和 `float` 完全一致）+ 7 位尾数。
所以它的**值域和 `float` 一样**（`±3.4e38`、次正规数、`Inf`、`NaN` 都在），
代价是十进制有效位只有约 3 位。

它不是 `_Float16`/`__fp16`：那两者是 5 位指数 + 10 位尾数，值域小、精度略高。
需要"值域跟 float 一样、带宽减半"就用 `bf16`，需要"精度更高、值域更小"用 `_Float16`。

## 写法

```c
bf16 a = 1.5;                     /* 0x3FC0 */
bf16 zero = 0;                    /* 整数初始化器也按数值转换 */
bf16 b = a * 2.0f;                /* 3.0：算术提升到 float，存回时再舍 */
double d = a;                     /* 3.0 → double，精确 */
int i = (int)a;                   /* 取整转换走 C 的 float→int 规则 */

bf16 arr[3] = { 0, 1.0, 2.0 };    /* 元素 2 字节，sizeof(arr) == 6 */
struct P { char c; bf16 v; };     /* v 的偏移 2、对齐 2 */
static struct P g = { 'x', 4.5 }; /* 静态初始化器在编译期就舍好 */
```

`bf16` 形参、返回值、指针、数组元素、结构体/联合体成员、`typedef` 都照常：

```c
static bf16 half(bf16 v) { return v * 0.5f; }
bf16 *p = &arr[1];
typedef bf16 scalar;
```

## 速查

| 项目 | 值 / 行为 |
|---|---|
| `sizeof(bf16)` | `2` |
| 对齐 | `2` |
| 值域 | 与 `float` 相同（指数 8 位） |
| 精度 | 尾数 7 位（十进制约 3 位有效数字） |
| 内存 → 值 | 读 2 字节，左移 16 位摊成 f32，**不引入误差** |
| 值 → 内存 | `r = (u + 0x7FFF + ((u >> 16) & 1)) >> 16`（RNE，ties-to-even） |
| `NaN` | 一律 `0x7FC0`（quiet，不进位成 `Inf`） |
| `+Inf` / `-Inf` | `0x7F80` / `0xFF80` |
| 最大有限值 | `0x7F7F`（约 `3.39e38`）；再乘 2 溢出成 `Inf` |
| 算术 | 提升到 `float`，结果存回 `bf16` 对象时舍入一次 |
| 比较 | 同 `float`（`==` / `<` / `NaN` 都不等于任何值） |

常见位模式（拿来对拍时用）：

| 数值 | `bf16` 位模式 | 备注 |
|---|---|---|
| `1.0` | `0x3F80` | |
| `1.5` | `0x3FC0` | |
| `2.5` | `0x4020` | |
| `-2.5` | `0xC020` | |
| `3.25` | `0x4050` | |
| `1.0 / 3.0` | `0x3EAB` | 值 `0.3339844`（torch 同口径） |
| `65536` | `0x4780` | |
| `100000` | `0x47C3` | 值 `99840`（RNE 后） |
| `0x3F800001` | `0x3F80` | tie 取偶数 |

## 陷阱

- **精度只有 3 位十进制**：`100000` 存进去读出来是 `99840`；不要把账目金额、
  时间戳这类"必须精确"的量放进 `bf16`。它适合机器学习里的权重/激活值。
- **存一次就少一次精度**：`bf16` 局部变量每次赋值都会舍入。想要"算的时候高精度、
  只在落盘时舍一次"，用 `float` 算、最后赋给 `bf16`。
- **整数常量按数值转换，不是按位模式**：`bf16 x = 0x3F80;` 是"整数 16256 转
  bf16"，结果是 `16256.0`（`0x467E`），**不是** `1.0`（`0x3F80`）。要按位模式
  构造就用 `union`/指针 reinterpret（见 `bf16_main.c6` 里的 `from_bits()`）。
- **`-0.0` 字面量**：c6 现在把 `-0.0f` 折成 `+0.0`（一元负号的老问题，与 `bf16`
  无关）；需要负零就从位模式 `0x8000` 构造。运行期 `0.0 - 0.0` 仍是 `+0`，
  `-x`（x 非零）符号正确。
- **只在 `.c6` 里是关键字**：`.c` 翻译单元里 `bf16` 仍是普通标识符
  （`int bf16 = 1;` 的老代码不会断）。所以头文件里要暴露 `bf16` 的接口时，
  该头只能在 `.c6` 里被包含，或者用 `typedef` 在 `.c6` 侧包一层。
- **按值传递和返回**在 ABI 上是 `float`（走 SSE 寄存器）；对象本身永远是 2 字节。
  自己手写 ABI 封装时按 `float` 对齐，不要按 2 字节对齐去凑寄存器。

## 实现位置

| 阶段 | 位置 |
|---|---|
| 类型（大小/对齐/判定） | `c6c/src/type.c6`：`TY_BF16` / `ty_bf16()` / `ty_is_float()` |
| 关键字门控 | `c6c/src/parse.c6`：`is_typename_tok()`、`parse_typespec()` |
| 读写与舍入 | `c6c/src/parse.c6`：`load_lval()` / `store_lval()` / `bf16_expand()` / `bf16_round_bits()` |
| 转换 | `c6c/src/parse.c6`：`gen_convert_impl()`（bf16 两条早退） |
| 静态初始化器 | `c6c/src/parse.c6`：`bf16_bits_of_f32()` + 两处浮点初始化器分支 |
| IR 类型 | `ir_ty_of(TY_BF16) == IRT_F32`（值一律 f32，**不新增 IR op**） |

IR 里没有 `bf16` 类型码：值是 f32，内存访问是 `IRT_U16` + 位运算。三个后端
（native / C99 / LLVM）共用同一套 IR，所以 bf16 不需要任何后端专属代码——
这也是它没有破坏自举 fixpoint 与 IR 指纹的原因。

## 验收

```sh
c6c/build/c6c -test c6c/tests/bf16_main.c6     # （已被 bf16-check.sh 覆盖）
C6C=c6c/build/c6c c6c/tests/bf16-check.sh      # native / C99 / LLVM 三后端 + 关键字门控
```

`bf16-check.sh` 检查 5 项：三个后端跑同一份断言、`.c` 里 `bf16` 仍是普通标识符、
`.c6` 里 `bf16` 是类型关键字。它挂在 CMake 的 `fast` 与 `check-all-c6c` 上。
