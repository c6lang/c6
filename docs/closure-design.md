# c6 函数字面量与闭包设计

状态：**V1 已实现**（无捕获的字面量 = 裸函数指针）。
V2（捕获式闭包）只给出设计，尚未实现——V1 的语法、命名与 ABI 都是它的
子集，所以 V2 落地时 V1 的代码一行不用改。

相关：[grammar.md §3.9](grammar.md)（语法与约束 C80–C83）、
[gc-design.md](gc-design.md)（托管引用，V2 的 env 用它）、
`tests/fn_lit.c` / `tests/errors/fn_lit.c` / `tests/abi/fn_lit.c`。

## 1. 语言形式

```
function-literal  = type-specifier , [ "!error" ] ,
                    "(" , [ parameters ] , ")" , compound-statement ;

void (*f)(int) = void(int x) { printf("%d\n", x); };   (* 显式声明 *)
void(int x) { printf("%d\n", x); }(1);                 (* 就地调用 *)
f = void(int x) { printf("%d\n", x); };                (* 推断声明 *)
```

三条设计决策，V1 与 V2 共用：

1. **字面量是表达式，值是函数**，不是"可调用对象"。所以
   `f(1)`、`apply(f, 1)`、`f` 存进结构体/数组、传给 C，全部按已有的函数
   指针规则走，不需要新的调用约定；
2. **没有新的值类别**。无捕获时值就是 `T (*)(P…)`，和写一个函数名完全等价
   （C ABI 零变化，`-emit-header`、`module` 名字改写都不用特殊处理）；
3. **体是稍后编译的**，和 `static inline` 一样在翻译单元末尾
   （`gen_function()`）发射，内部名 `__c6_fn_<序号>`，`static`。

## 2. V1：无捕获（已实现）

```c
static int offset = 100;                  /* 文件作用域：体里看得见 */

int (*f)(int) = int(int n) { return n + offset; };   /* 可以 */
```

体里只看得见**自己的参数**和**文件作用域**的名字。写在外层的局部变量、
形参、块作用域 `typedef`/tag 都看不见：

```c
int x = 1;
int (*f)(void) = int() { return x; };     /* 错误 C80：捕获了 x */
```

**为什么对捕获报错而不是"就按引用用"**：字面量的体在函数返回之后才可能被
调用（存进结构体、交给 C 保存、进数组），而局部变量在返回时就已经消失。
按引用捕获等于给用户一个必然悬空的读写窗口，而这门语言的其余部分（托管
引用、借用形参 C70、`own`）都在刻意避免这类窗口。按值捕获也不是小改动，
见 §3。

实现上，捕获检测是"否定表"：`C6Lit.caps` 在解析字面量头时收集当前块作用域
里的所有名字（`local_stack` 中 `sym_scope != 0` 的标识符），体编译期间任何
一次符号解析（值、`typedef`、tag 三条路径）命中表内名字就报 C80——不需要
做自由变量分析，也不会漏。

## 3. V2：捕获式闭包（设计，未实现）

### 3.1 值形状

有捕获时字面量的类型变成**胖指针**，用 GC 的 `@struct` 承载环境：

```c
(* 源码 *)            (* 等价的类型 *)                            (* 布局 *)
int() { return x; }   @struct __c6_closure_1 {                    code: 8B
                          int (*code)(@__c6_env_1 *, …);            env:  8B（@ 服务）
                          @__c6_env_1 *env;                      }  16B
                      @__c6_env_1 { int x; }
```

* `env` 是 `new` 出来的托管对象，字段就是被捕获的那些变量（**按值**拷贝）；
  捕获 `@T` 时拷进去的是引用（+1），捕获切片时拷贝 `{data, len}`（借用语义，
  与形参一致：切片本身不拥有元素）；
* 调用点改写：`f(1)` → `f->code(f->env, 1)`；`f` 是胖指针，`->` 走普通
  托管引用规则（`f = NULL` 就是放手）；
* `__c6_env_N` 必须有描述符（`c6_gc_collect()` 已经会生成），这样 env
  里的 `@T` 字段随 env 一起释放；env 之间可能成环（`x` 捕获了 `y` 的闭包），
  所以 env 的结构体也在静态环检测（C66）的管辖范围内——捕获图成环就报错，
  和普通 `@T` 一样。

### 3.2 代价与约束

胖指针**不能**直接交给 C（C 只认 8 字节函数指针），这正好是 V1 只做无捕获
的原因：无捕获的字面量永远是裸指针，捕获的字面量永远是胖指针，两者的区别
在类型上，不会在运行期"看起来一样但行为不同"。

由此 V2 需要补的三条约束（编号留空，实现时接着 C83 往后排）：

- 捕获式闭包不能作为 C 函数指针传递（`qsort` 的比较函数必须无捕获）——
  报错信息里给出改法：把参数显式传进去；
- 捕获式闭包进 `go` / `async` 时，env 必须是跨线程类型（`shared`），
  否则与 C73 同一条理由；
- 捕获式闭包不能按值拷贝（`@struct` 与 `@T` 同规则，C68）。

### 3.3 实现要点（相对 V1 的增量）

| 位置 | V1 现在 | V2 增量 |
|---|---|---|
| `c6_lit_cap_check()` | 命中即报 C80 | 命中就把该名字记进 `C6Lit.captures`，不再报错 |
| `c6_lit_parse()` | `static` 函数 + 函数指示符 | 再建 `__c6_env_N` 的 `@struct` 类型、`new` 一个 env、把捕获变量 `vstore` 进 env 字段，值类型换成胖指针 |
| `c6_lit_emit()` | `gen_function(lit->sym)` | 给函数体加一个隐藏的首参数（env 指针），体里捕获名的解析指向 `env->field` |
| 调用点 | 无需改动 | `vstore` / 参数传递时把胖指针拆成 `code` + `env`（或在 type 上加 `VT_CLOSURE`，让 `gfunc_call` 自己拆） |
| `-emit-header` | 跳过（`static`） | 胖指针要用到 `__c6_closure_N` 的 typedef，必须能写出这个名字 |

## 4. 明确不做

- 捕获可变引用（`int() { x++; }` 改外面的 `x`）：要捕获就需要"格子"语义，
  和现在的栈变量模型冲突；
- 捕获 `this`（方法里写字面量）：方法体里 `this` 是形参，按 V1 报 C80；
  V2 里它同样是一个"借用形参"，能否捕获取决于 borrow 逃逸分析（C70）；
- 语法上的捕获列表（`[x, &y]`）：`[` 在 c6 里已经是下标/切片，不引入新记号；
  V2 的捕获是由体里的自由名字**隐式**决定的（全部按值）；
- `bare` / `noescape` 标注：V1 的"无捕获即裸指针"已经覆盖了这条需求。

## 5. 与其它 c6 特性的关系

| 特性 | 交互 |
|---|---|
| `!error` | 字面量可以有 `T!error` 返回类型，`try` / `catch` 照常用（`tests/fn_lit.c`） |
| `defer` / `err` | 体里可以写，体被 `gen_function()` 当成普通函数编译，清理链照旧生成 |
| `@T` / `new` / 切片 / 元组 | 参数和返回值都可以是这些类型；V1 不拷贝任何东西，所以没有额外规则 |
| `static inline` | 体里可以写字面量：两者都是 TU 末尾发射，`c6_lit_flush()` 在 `gen_inline_functions()` 的同一个循环里跑 |
| `module` / `-emit-header` | `__c6_fn_N` 以 `__` 开头且 `static`，不改写、不导出 |
| C99 后端 | 字面量就是普通 `static` 函数，`-o *.c` 输出的是可读的 C（`make c99test` 覆盖） |
| `test` | `tests/fn_lit.c` 用 test 块覆盖正常用法，`tests/errors/fn_lit.c` 覆盖 C80–C83 |
