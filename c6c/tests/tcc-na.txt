# tests2 里「在 c6c 现有架构下不可达」的用例，一行一个：用例名 <TAB> 原因
#
# 记分板把它们单独算一类（n/a），不算失败；反过来，**不在**这张表里的失败
# 才是真失败——这样这份记分板才能当验收闸门用，而不是"差多少条"的进度条。
# 每一条的理由都写死了具体卡点，不许写"暂不支持"这种糊话。
104_inline	要 tcc 自己 libtcc1.a 里的 check_exports；上游 tests2/Makefile 自己就是用 104+_inline.c 替代（只编不跑），而那份变体 c6c 已干净编过
113_btdll	需要 tcc 自己的 tcc_backtrace
114_bound_signal	要 tcc 的 -b 边界检查运行时：用例有 main、会被真跑，光补 __sigsetjmp 不够（要 pthread/fork/signal/longjmp 一整套）
140_arm64_extasm	arm64 汇编（上游在 x86-64 上也跳）
145_winarm64_interlocked	要 windows.h + win-arm64 内建函数（上游也跳）
99_fastcall	i386 的 fastcall 调用约定（上游只在 i386 上跑）
94_generic	要**指向对象的**限定符进类型 id：`const int *` 必须和 `int *` 不同 id（指针层限定符已经有了，缺的是 `const` 修饰基类型这一层；`_Generic(ptr, int *:1, int * const:2, default:20)` 现在是 2、应为 20）
112_backtrace	要 tcc 的 `-dt` 自动展开 `test_*` 宏并反复重跑 + `-b` 边界检查运行时；上游 tests2/Makefile 给这条用例加了 `FLAGS += -dt -b`，c6c 没有 `-dt`（同族的 113_btdll 已按"需要 tcc_backtrace"记为 n/a）
102_alignas	`_Alignas` 在声明位置**只解析不落地**（parse.c6 的 `_Alignas` 分支原注释就是"直接忽略"）：全局对象按 `ty_align_of(类型)` 布局、`__alignof__(对象)` 也只看类型，所以 `alignof(i1)==16` 等断言是 `0 0 1 0`（应为 `1 1 1 1`）。要过这条得给 Sym 加对齐字段 + `data_alloc` 用 max(类型对齐, 用户对齐) + `__alignof__` 认对象；告警口径（第一行 `type defaults to int`）已对齐，卡的是对齐语义本身
129_scopes	`__LINE__` 在宏体里报调用点行号**已修**；剩下的全是作用域语义差：`sizeof(enum{in=1})` 里的枚举常量泄漏到外层块（12/17/22/27 行那几处 "//OOPS" 要求 `!in`）、105 行 `f5() == 10 + 4`、126 行 `i6 == 11 && f6(22) == 22` 的块内遮蔽、末尾 `xx7 (2)` 输出 `0 0`（应 `12 34`）。要过这条得让 sizeof/类型名里的 tag 声明按语句作用域回收，并修块作用域遮蔽与静态初始化
