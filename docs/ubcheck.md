# c6 程序的未定义行为检查（`stdub`）

> **状态**：现行 · **层**：标准库 / 工具 · **索引**：[文档索引](README.md) ·
> **相关**：[stdlib.md](stdlib.md)（第八十四批）、[grammar.md](reference/grammar.md)、
> [`examples/stdub.c6`](../examples/stdub.c6)

`std/analysis/` 是**用 c6 写的 c6 分析工具链**：分词（lex）→ 解析（parse）→
未定义行为检查（ub），`examples/stdub.c6` 是这三件的命令行。它不链接 libc 之外的
东西、不做动态执行，读源码就出报告——报告里**每一条都带具体修法和一整行可以直
接粘回源码的代码**。

```
       源码 ──► lex ──► parse ──► ub ──► 报告（文件:行:列 + 修法 + 代码）
                 词法      务实 AST    13 类检查
```

## 1. 跑起来

```sh
cmake --build build --target std-ub                   # 先编出检查器（build/stdub），并跑内置演示样例
./build/stdub 你的文件.c6      # 真实文件，可以给多个
./build/stdub std             # 给目录就**递归**扫里面所有 *.c6（子目录一起）
./tcc/c6 --ub 你的文件.c6      # 同一个检查器，从编译器入口调（等价于上面这条）
./build/stdub -q 你的文件.c6   # --quiet-uncertain：只报「一定」
./build/stdub -W 你的文件.c6   # --strict：安全门模式（见下）
./build/stdub -S 你的文件.c6   # --sound：健全模式（证明不了的访问也算失败）
```

**退出码**：

| 码 | 含义 |
|----|------|
| `0` | 干净（或只剩「可能」级） |
| `1` | 至少一条「一定」级问题 |
| `2` | 用法错误 / 文件读不出来 / `--strict` 下存在「没看懂」的构造 |

**`--strict`（安全门）** 是把「没报」变成「查过了」的开关：在这个模式下

* 「可能」级也算失败（`1`）；
* 只要解析器有**没认出来的构造**就失败（`2`）——因为那些区域没被检查，
  「没报问题」不能算通过。

放进 CI 就是一行：

```sh
cmake --build build --target std-ub                                   # 先把工具本身编出来
./build/stdub -W src/*.c6 || exit 1            # 有任何不确定/没看懂就不给过
```

不带 `--strict` 时它是个**建议器**；带 `--strict` 时它是个**门**。

`--sound`（`-S`）比 `-W` 更狠一级：**任何「说不准」的访问都算失败**。它把每处
证明不了的下标/解引用都报成 `UB-UNAUDITED`，要求二选一：

* 把边界写清楚让检查器能证明（`if (i < 0 || i >= n) return -1;` 之后再访问）；
* 或者在这一行标 `/// c6ub-proven`，声明「人工审计过这一处」。

这就是「健全」的成本：**没证明过的不许当成没问题**。实测整个 `std/`：365 个模块里
只有 9 个能过 `--sound`，其余 356 个共有 **15 380 处**访问没有证明——见 §8。

「可能」级不改变退出码：它能进 CI 的日志，但不会把构建拦下来。

## 2. 输出怎么读

```
demo.c6:2:44: 一定 [UB-OOB] 常量下标越界
    2 | int oob(void) { int a[4] = { 0 }; return a[4]; }
        | a 只有 4 个元素（合法下标 0..3），这里用了下标 4
   修法 | 把下标 4 改成 3 以内；要是这个下标非留不可，就把数组声明成 int a[5];
   代码 | a[3]   // 换掉越界的下标
```

* 第一行是**惯用的编译诊断格式**：`文件:行:列: 一定|可能 [编号] 标题`。
  行号从 1 开始、列号按字节算，跟 `gcc`/`tcc` 一样，能被编辑器/CI 直接解析。
* `2 |` 是出问题的**源码原文**（不含行号缩进的正文），`|` 后面那行是
  `Finding.msg`：一句话说清「为什么这是 UB」。
* `修法 |` 是 `Fix.text`：**一句中文**，说清改什么、改成什么。
* `代码 |` 是 `Fix.code`：**可直接粘贴的一整行**（不是片段、不留占位符），
  占位符一律换成具体名字/下标/常量。多行代码（比如「改成让调用方传缓冲区」）
  会续行打印，每行都带同样的 `代码 |` 前缀。
* 末尾一行汇总：`stdub: 演示样例共 9 条（一定 8、可能 1）`，被 `c6ub-ignore`
  压掉的条数也会报（`压掉 N 条`），还会报两类「没有结论」的账：
  `N 处没看懂（未检查）`（解析器没认出来的构造）与 `另有 N 处访问说不准`（下标/
  解引用说不准，静态判不了，只能靠 `c6 -b` 兜）。两条都为 0，报告才算「真的干净」。
* 如果解析器有**没认出来的构造**，会额外打一行警告，点名行号列号：

  ```
  x.c6: 有 2 处构造没认出来，这些区域**没有**检查：12:5、30:9
  ```

  这条存在的意义是：**「没报」不等于「查过了」**。

## 3. 十五类检查

每条都给「判据 / 什么时候报」和「修法形状」——修法不是散文，是能落地的动作。

| 编号 | 查什么 | 判据 | 修法形状 |
|------|--------|------|----------|
| `UB-DIV0` | `a / 0`、`a % 0` | 除数是常量 0（字面量或折出来的 0） | 常量 0 → 换成非 0 常量（给整行代码）；两边都是常量 → 删掉这段 |
| `UB-INTMIN` | `INT_MIN / -1`、`INT_MIN % -1` | 被除数是 `INT_MIN`、除数是 `-1` | 改成先判符号再用 `-(x)`，或换成无符号/64 位 |
| `UB-OVFL` | 常量加减乘溢出 | 常量折叠结果超出 int 范围 | 给一个操作数加 `(i64)` 强转，整行代码现成 |
| `UB-SHIFT` | 移位量 `< 0` 或 `>= 32` | 移位量是常量 / 常量折出来 | 常量 → 换成 0..31；变量 → `x & 31` |
| `UB-OOB` | 数组 / 堆块越界 | 下标能折成常量并落在 `0..n-1` 外；**循环变量有常量范围**（`for (i = 0; i < 7; i++) a[i]`，a 只有 4 格）；`*(a + k)` 的常量偏移；`strcpy(dst, "字面量")` 塞不进 dst | 换成合法下标；或把数组 / 循环上界改到放得下（给整行声明） |
| `UB-NULL` | 解引用空指针 | 指针是 `NULL` / 赋过 0 的字面量 | `if (!p) { … return …; }` 守卫 |
| `UB-UAF` | `free` 之后再读/再写 | 直线追到「已经释放」：同函数、**经别名**（`q = p`）、**跨一层函数**（被调函数无条件 free 掉的实参）。`defer free(p)` 只是**排队**，它之后的使用仍然合法 | 把 `free` 挪到作用域末尾（`defer free(p);`）或删掉这次使用 |
| `UB-DFREE` | 同一指针 `free` 两次 | 第二次 `free` 前状态已是 `VS_FREED`（含 `defer free` + `free` 撞车） | 删掉重复的那次 `free`；或释放后立刻 `p = NULL;` |
| `UB-ESCAPE` | `return &局部变量`、`return 局部数组` | 返回表达式直接取局部地址 | 改成调用方传缓冲区进来（给函数签名），或按值返回 |
| `UB-UNINIT` | 读 `malloc` 出来没写过的内存 | 堆块状态是 `VS_HEAP`（没写过） | 先写一遍，或把 `malloc` 换成 `calloc`（给整行） |
| `UB-VLA` | 零长度数组 | 长度常量折成 0 | 长度改成 ≥ 1 的常量 |
| `UB-OVERLAP` | `memcpy` 源与目标重叠 | 两个实参是同一个对象（同名标识符） | 换成 `memmove` |
| `UB-NULLARG` | `memcpy`/`memset` 等传常量 0 指针 | 实参是字面量 0/`NULL`，且该位置必须非空 | 传真实缓冲区，或加空指针守卫 |
| `UB-BADFREE` | `free(&局部变量)` | free 的实参是栈上变量的地址 | 删掉这次 free（栈内存自动回收） |
| `UB-UNAUDITED` | 没证明过的内存访问（只在 `--sound` 下报） | 下标/解引用的边界或状态静态上定不下来，且没标 `c6ub-proven` | 补边界判断，或标 `/// c6ub-proven` 承认人工审计 |
| `UB-RACE` | 跨线程共享可写状态 | 地址被交给**起线程**的 API（`thread_spawn` / `thread_create` / `pthread_create` …）的全局/静态变量；或者同一个局部变量/堆块交给过**两个**线程入口 | 用 `std.os.sync` 的锁或 `std.core.atomic` 的原子量包住；共享缓冲区改成每线程一份（都给到代码行） |

## 4. 能追到多远（分析能力清单）

「一定」不是猜出来的，每条都有明确的推理规则。当前覆盖：

| 能力 | 规则 | 例子 |
|------|------|------|
| 常量折叠 | 字面量 + 可以折叠的常量表达式 | `7 / (3 - 3)` → 除零 |
| 数据流 | 函数内直线地追指针状态（堆/已释放/已排队释放/空） | `p = malloc(8); free(p); p[0]` |
| 别名 | `q = p` 记下拷贝链，顺链找到根对象 | `q = p; free(p); q[0]` |
| 跨函数（内联） | 调用点把被调函数体**放到当前上下文里再走一遍**：实参状态/堆块字节数/常量实参都带进去，回来把「释放了哪个实参」「写过哪个 `*out`」写回调用方。深度 3、单次分析最多 200 次展开、只展开 ≤48 条语句的小函数，递归立刻停 | `drop2(p) → drop1(p) → free(p)`；`take(p, 9)` 里知道 p 只有 4 字节；`release(&p)` 之后 p 已释放 |
| 跨函数摘要（兜底） | 展开不了时退回「这个函数无条件释放了第几个参数」的摘要 | 大函数里的 `free(param)` 仍能影响调用点 |
| 谓词 / 返回值契约 | 函数体里检查过某个指针参数 ⇒ `if (!ok(p)) return;` 之后 p 非空；`r = f(p); if (r != 0)` 之后 p 非空 | `if (!ok(self)) return;`、`int r = peek(self, t); if (r == 1) self->pos = …` |
| 范围推理 | `for (i = lo; i < hi; i++)` 给循环变量记常量区间 | `for (i = 0; i < 7; i++) a[i]`（a 有 4 格） |
| 守卫识别 | `if (p)` / `p && …` / `!p \|\| …` / `if (!p) return;` 之后视为非空 | `if (!t \|\| t->kind != X)` |
| 分支汇合 | 两条分支状态不一致就退回「未知」，不硬报 | `if (c) p = malloc(8);` 之后不再断言 p |
| 出参 | `f(&x)` 且被调函数体里有 `*p = …` ⇒ 回来之后 x 状态作废；被调函数 `free(*p)` ⇒ 调用方那个变量算已释放 | `get(&bits); bits[0]`、`release(&p); p[1]` |
| 字符串长度 | `strcpy/strcat` 的字面量长度对得上目标数组 | `char b[4]; strcpy(b, "hello")` |
| realloc | `q = realloc(p, n)` 之后 p 作废（原地 `p = realloc(p, n)` 不算） | `q = realloc(p, 32); p[1]` |
| 线程 | 全局变量地址进线程入口 ⇒ 可能的数据竞争 | `thread_spawn(worker, &g)` |
| 位宽 | 按类型名认 `u64`/`size_t`…，说不准就当不知道，不硬报 | `u64 v; v >> 33` 合法 |

**说不准就不说**是这套规则的核心纪律：宽度、别名、范围任何一环拿不到常量，
就退回「可能」，或者干脆不报——绝不用「一定」的语气讲猜出来的话。

## 5. 「一定」与「可能」的口径

* **一定（`CONF_CERTAIN`）**：不依赖运行时就能定死。常量折叠出来的结果、
  沿直线代码追出来的指针状态、同一表达式里看得到的同一对象。
* **可能（`CONF_POSSIBLE`）**：要合上调用约定、别名或运行时才知道。例如对
  `malloc` 出来的内存的读（可能别处已经写过）、非字面量下标的越界。

口径固定下来是为了**让报告可用**：每条「一定」都应该能当场改掉，每条「可能」
都应该经得起「你凭什么这么说」的追问。所以宁可降级，也不硬报——更不会报
「可能有风险」这种说不出改法的东西（说不出具体改法的发现直接不生成）。

`UbOpts.quiet_uncertain` 非 0 时只留「一定」级。

## 6. 抑制：`c6ub-ignore`

在**出问题的行**上（或紧挨着的上一行）写注释：

```c
int a[4] = { 0 };
return a[4];   /// c6ub-ignore UB-OOB
```

* `c6ub-ignore`：这一行的**所有**发现都跳过。
* `c6ub-ignore UB-OOB`：只跳过这一个检查，同行的别的发现照报。
* `c6ub-proven`：只压 `UB-UNAUDITED`，意思是「这一处我人工审计过，接受」。
  `--sound` 下它就是唯一的放行方式，所以它应该**少而明确**，最好带一句理由。
* 被压掉的条数在 `ub_suppressed()` 里，CLI 会在汇总行里说「压掉 N 条」——
  **抑制不等于消失**，它只是被计数。

用它的场合就两个：故意的边界代码（比如自己实现的内存池在末尾多留一格），
以及检查器的已知误报。别拿它当「先关掉再说」。

## 7. 三件套的 API（自己写工具时）

```c
import std.analysis.lex;
import std.analysis.parse;
import std.analysis.ub;

Arena a = arena_make(1 << 20);

/* 1) 词法：Lexer 是**纯值**，结构体赋值就是快照，回滚直接 *self = save */
Lexer lx = lx_open(S("int main(void) { return 0; }"));
for (Token t = lx_next(&lx); t.kind != TK_EOF; t = lx_next(&lx))
    printf("%d:%d %.*s\n", t.line, t.col, (int)t.text.s.len, t.text.s.ptr);

/* 2) 语法：AST 全放调用方的 Arena，Program 里是函数表/符号表/错误账 */
Program *p = parse_program(&a, src);
printf("nerr=%d nfunc=%d nstmt=%d\n", parse_errors(p), p->nfunc, p->nstmt);

/* 3) UB 检查：先设 Program，再跑 */
UbOpts o = ub_opts_default();
Ub *u = ub_open(&a, S("x.c6"), src, o);
ub_set_program(u, p);
ub_run(u);
for (Finding *f = ub_findings(u); f; f = f->next)
    printf("%s:%d:%d: %s [%s] %s\n", f->file.s.ptr, f->line, f->col,
           ub_conf_name(f->conf), ub_check_name(f->check), f->msg.s.ptr);
```

要点：

* `parse_program` **不抛错、不中断**：不认识的构造记进 `Program.nerr`，并把前
  32 处 `(line,col)` 留在 `Program.errl/errc` 里。用
  `ub_not_analyzed()` 拿到「没看懂几处」，自己决定是警告还是拒绝出报告。
* `Lexer` 里没有堆分配，`lx_peek(&lx, n)` 只读不前进；`lx_open` 保的是**调用方
  的切片**，源码得活到分析结束。
* 所有 `Str`/`Token`/`Node` 都是指向**原源码或 Arena** 的视图，没有拷贝、没有
  二次分配；一个 100 KB 的文件跑完不留垃圾。

## 8. 「通过检查」= 什么级别的安全

先把话说明白：**静态检查给出的是「可判定的那一层」，不是全程序的证明。**
c6 有裸指针、指针算术和 `malloc/free`，「过检」能达到的级别要按下面这张梯子看。

| 级别 | 形态 | 通过之后能保证什么 | c6 里谁来提供 |
|------|------|--------------------|---------------|
| L0 | 什么都不查 | 无 | — |
| L1 | 编译期语法 / 类型检查 | 程序能编过 | `c6` 编译器 |
| L2 | **函数内可判定的 UB**（本工具，第八十四批） | 常量能定死的除零/溢出/移位/越界/空指针/双重释放/释放后使用/返回局部地址…（上面十五类）一个都没有 | `stdub` |
| L3 | 全程序流敏感 + 别名 + 区间分析 | 变量的实际取值范围、跨函数的数据流都算进来 | 本工具的**一层函数摘要 + 别名 + 循环范围**只覆盖了 L3 的一小块 |
| L4 | 运行时插桩（ASan / valgrind / `-b`） | **执行到的每一条路径**上越界/UAF/非法访问都会当场炸出来 | `c6 -b`（TCC 内置的 bounds/memory checker） |
| L5 | 类型系统强制（Rust / Go） | 编译期就排除整类错误（Rust 的 safe 子集**没有** UB） | c6 的语言特性只做了一部分 |

对照实测（同一批用例）：

* 常量 / 别名 / 一层摘要 / 循环范围 / 守卫 / realloc 能判定的 15 个真实缺陷：
  **15/15 全部报出**，每条都带具体修法。
* 需要运行时才能知道的 8 个缺陷（下标来自参数、`strcpy` 源来自参数、`*(base + k)`
  的 base 来自参数…）：**4/8 报出**，另外 4 个静态上不可判定——它们属于 L4 的地盘。
* 拿 `std/` 全部 357 个模块跑一遍：**0 条误报**、**0 处「没看懂」**（这是「报告可用」
  的底线，也是 `cmake --build build --target ubcheck` 的通过条件）。

所以：

* `stdub -W` 通过 ⇒ 代码里**不存在**上面十五类里任何可静态判定的 UB，
  并且**没有「没看懂」的区域**（`--strict` 会把没认出来的构造判失败）。
* 但它**不等于** Rust 级内存安全：Rust 的保证来自「借用检查器在编译期证明所有安全
  代码无 UB」，而 c6 的裸指针让「变量下标的越界、运行期才知道的别名、数据竞争」
  在静态上不可判定——绕不过去。

**要摸到 Rust 级，得把三层叠起来用**（缺一不可）：

```sh
./build/stdub -W src/*.c6          # 1. 静态门：可判定项 + 不许有没看懂的构造
c6 -b -I . -o app src/*.c6         # 2. 运行时门：-b 给每次访问加边界/内存检查
./app && cmake --build build --target stdtest              # 3. 跑起来：把路径真的走一遍（含单元测试）
```

仓库里这两层已经合成一个目标：

```sh
cmake --build build --target safegate     # ubcheck（静态，整个 std/）+ c6 -b 探针（证明运行时层是活的）
```

给目录时会用 `std.os.walk` 往下钻：只收普通文件、后缀 `.c6`，符号链接不跟随，
一层最多 8192 个文件、目录深度 32（`std.os.walk` 的上限）；整个 `std/`（369 个模块）
扫一遍约 6 秒。

`stdub` 的汇总行会给出「另有 N 处访问说不准」——这就是**静态层的边界**，它对应
`ub_unproven()`（`ub_accesses()` 是访问点总数）。`--strict` 会把这行打到 stderr，
提醒这条代码库有多少内存访问交给运行时兜。

`safegate` 的第二半跑 `tests/ub/ubsmoke.c6`：那处越界的下标来自函数参数，**静态层按
「说不准就不说」放过**，`-b` 必须当场抓住（`BCHECK: … is outside of the region`，
进程非 0 退出）。抓不住就说明运行时层没生效，门不放行。

* 第 1 层保证「明显错的东西进不了仓库」；
* 第 2 层把「运行到的路径」上的越界 / 释放后使用 / 非法访问变成**当场失败**，
  而不是静默 UB（`-b` 会打印 `BCHECK: … is outside of the region` 并终止）；
* 第 3 层决定第 2 层能覆盖多少路径——测试没走到的分支，`-b` 也没机会查。

### stdub 能不能做到 L4 / L5

**L4（运行时检查）：不能由 stdub 本体做到，但可以托管。** L4 的定义就是「在真实执行
里插检查」，一个纯静态扫描器做不到。做法是把两层拼起来——这就是 `cmake --build build --target safegate`：

* 静态层 `stdub -W`：可判定项清零、没看懂的构造判失败；
* 运行时层 `c6 -b`：实测能抓住**堆越界、栈数组越界、释放后使用、重复释放、
  `memcpy` 超长**（`BCHECK: … is outside of the region` / `freeing invalid region` /
  `invalid pointer … in memcpy dest`，进程 `exit(255)`）；
* 但 `-b` **抓不到**：未初始化读、内存泄漏、数据竞争、以及没执行到的分支
  （实测：`int *p = malloc(16); return p[0];` 和只 malloc 不 free 都是 `exit 0`）。

所以「stdub + `-b`」合起来 ≈ **L4 的检出能力**（不是证明）：跑到哪儿查到哪儿。

**L5（类型系统强制，Rust 级）：静态工具单靠自己做不到，原因不是工程量，而是健全性。**
要给出「过检 ⇒ 没有 UB」的保证，检查器必须**拒绝一切它证明不了的访问**——这正是
`--sound` 干的事。它跑出来的结果就是答案：

```
std/ 365 个模块：--sound 通过 9 个，356 个未通过，共 15 380 处访问没有证明
（最多的 std/analysis/ub.c6 799 处、std/text/regex.c6 276 处）
```

也就是说：c6 里**绝大部分内存访问的证据不在源码里**（长度来自参数、来自结构体字段、
来自运行期计算），静态分析拿不到。要让过检等价于 Rust 的保证，只有三条路：

1. **代码按安全子集写**：把 `--sound` 的账目一点点清零（补边界判断或标
   `c6ub-proven`）。这是「用纪律换保证」——Rust 的 `unsafe` 审计也是这么做的，
   只不过 Rust 让安全代码**不需要**审计；
2. **运行时兜底**：`-b` 留在 CI 和测试里，把「没证明的」变成「跑到就查」；
3. **语言级改造**：所有权/生命周期类型 + `Send`/`Sync` 规则（借用检查器）。这才是
   L5 的真正来源——它要求 c6 在类型系统里表达「谁拥有这块内存、活多久、能不能跨线程
   共享」，是编译器工作，不是 lint 工作。

一句话：**stdub 能把「能判定的」判到底，能把「判不了的」明确标出来（不静默），
但把 c6 变成 Rust 需要语言本身长出所有权类型。** 这不是检查器的野心边界，而是
「静态证明」与「裸指针」之间的事实边界。

**还差什么才算 Rust 级**：① 没有 `unsafe` 逃逸面（c6 的裸指针要收进
「安全子集」才谈得上证明）；② 数据竞争的规则（`Send`/`Sync` 那一套；c6 的
async 是单线程协作式，但 `std.os.thread` 共享状态仍需人工保证）；③ 所有权
与生命周期（现在靠 `defer`/arena 约定）。这三条都是**语言设计**层面的工作，
不是一个 lint 能补的——本工具能做的是：把语言层面没堵住的口子，在**能判定的
地方全部堵死**，判定的地方之外用运行时检查兜住，并把「没看懂」明确报出来。

## 9. 限制（诚实清单）

这些是**设计上就不做**的，不是「以后再说」：

1. **跨函数是调用点内联，不是全程序数据流**：展开深度 3、每次函数分析最多 200
   次、只展开 ≤48 条语句的小函数，递归立刻停——这是为了别组合爆炸。展开不了的
   （大函数、递归、超过预算）退回「无条件释放了第几个参数」的摘要，所以
   `drop2 → drop1` 这种两层传递能追，三层以上或大函数里的传递可能就断了；
   通过全局变量、结构体字段传递的指针仍然追不到。
2. **别名只认直接拷贝链**：`int *q = p;` 认；`q = p + 1`、结构体字段里存的
   指针、通过数组下标的别名不认。
3. **不认 `realloc` 之后的旧指针**：`realloc` 按「新分配」处理。
4. **堆块大小只认常量长度**：`malloc(n)` 时 `n` 不是常量就只记「未知大小」，
   越界检查跳过（不会猜成 0）。
5. **不展开宏、预处理和 `#include`**：看的是文本层面能认出来的 c6 构造；宏生成
   的代码不在视野里。
6. **类型模型是简化的**：`int` 按 32 位、指针按 8 字节、`i64`/`u64` 按 8 字节；
   不对齐/严格别名（strict aliasing）这两类 UB **不查**。
7. **`switch` 穿透、无限循环、`goto` 跨作用域**这些控制流细节按直线代码近似：
   分支汇合处的变量状态取「两边一样才算已知」，否则降级成「未知」。
8. **解析器不认的构造一律不猜**：内联汇编里带冒号的 `__asm__(… : … : …)`、
   部分 freestanding 例子里的方言，会走「没认出来」这条路，并在报告里点名——
   `std/` 下全部 `.c6` 与绝大多数 `examples/*.c6` 都能被完整解析（`nerr = 0`）。

## 10. 回归

```sh
cmake --build build --target std-ub      # 编译并跑 examples/stdub.c6（演示 9 条：一定 8、可能 1）
cmake --build build --target stdtest     # 三个模块的 test 块全绿（349 个模块、0 failure）
```

`std/analysis/ub.c6` 自己的用例覆盖了每类检查的正例和反例，也包括「只报一遍」
「干净的程序一条都不报」「`c6ub-ignore` 能压一行、也能只压一个检查」这些
容易写歪的行为。
