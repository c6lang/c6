# c6 程序的未定义行为检查（`stdub`）

> **状态**：现行 · **层**：标准库 / 工具 · **索引**：[文档索引](README.md) ·
> **相关**：[stdlib.md](stdlib.md)（第八十四批）、[grammar.md](reference/grammar.md)、
> [`examples/stdub.c6`](../examples/stdub.c6)

`std/analysis/` 是**用 c6 写的 c6 分析工具链**：分词（lex）→ 解析（parse）→
未定义行为检查（ub），`examples/stdub.c6` 是这三件的命令行。它不链接 libc 之外的
东西、不做动态执行，读源码就出报告——报告里**每一条都带具体修法和一整行可以直
接粘回源码的代码**。

```
       源码 ──► lex ──► parse ──► ub ──► 报告（文件:行:列 + 修法 + 代码）
                 词法      务实 AST    13 类检查
```

## 1. 跑起来

```sh
make std-ub                   # 内置演示样例（9 条）
./build/stdub 你的文件.c6      # 真实文件，可以给多个
./build/stdub --quiet-uncertain 你的文件.c6   # 只报「一定」
```

**退出码**：

| 码 | 含义 |
|----|------|
| `0` | 干净（或只剩「可能」级） |
| `1` | 至少一条「一定」级问题 |
| `2` | 用法错误 / 文件读不出来 |

「可能」级不改变退出码：它能进 CI 的日志，但不会把构建拦下来。

## 2. 输出怎么读

```
demo.c6:2:44: 一定 [UB-OOB] 常量下标越界
    2 | int oob(void) { int a[4] = { 0 }; return a[4]; }
        | a 只有 4 个元素（合法下标 0..3），这里用了下标 4
   修法 | 把下标 4 改成 3 以内；要是这个下标非留不可，就把数组声明成 int a[5];
   代码 | a[3]   // 换掉越界的下标
```

* 第一行是**惯用的编译诊断格式**：`文件:行:列: 一定|可能 [编号] 标题`。
  行号从 1 开始、列号按字节算，跟 `gcc`/`tcc` 一样，能被编辑器/CI 直接解析。
* `2 |` 是出问题的**源码原文**（不含行号缩进的正文），`|` 后面那行是
  `Finding.msg`：一句话说清「为什么这是 UB」。
* `修法 |` 是 `Fix.text`：**一句中文**，说清改什么、改成什么。
* `代码 |` 是 `Fix.code`：**可直接粘贴的一整行**（不是片段、不留占位符），
  占位符一律换成具体名字/下标/常量。多行代码（比如「改成让调用方传缓冲区」）
  会续行打印，每行都带同样的 `代码 |` 前缀。
* 末尾一行汇总：`stdub: 演示样例共 9 条（一定 8、可能 1）`，被 `c6ub-ignore`
  压掉的条数也会报（`压掉 N 条`）。
* 如果解析器有**没认出来的构造**，会额外打一行警告，点名行号列号：

  ```
  x.c6: 有 2 处构造没认出来，这些区域**没有**检查：12:5、30:9
  ```

  这条存在的意义是：**「没报」不等于「查过了」**。

## 3. 十三类检查

每条都给「判据 / 什么时候报」和「修法形状」——修法不是散文，是能落地的动作。

| 编号 | 查什么 | 判据 | 修法形状 |
|------|--------|------|----------|
| `UB-DIV0` | `a / 0`、`a % 0` | 除数是常量 0（字面量或折出来的 0） | 常量 0 → 换成非 0 常量（给整行代码）；两边都是常量 → 删掉这段 |
| `UB-INTMIN` | `INT_MIN / -1`、`INT_MIN % -1` | 被除数是 `INT_MIN`、除数是 `-1` | 改成先判符号再用 `-(x)`，或换成无符号/64 位 |
| `UB-OVFL` | 常量加减乘溢出 | 常量折叠结果超出 int 范围 | 给一个操作数加 `(i64)` 强转，整行代码现成 |
| `UB-SHIFT` | 移位量 `< 0` 或 `>= 32` | 移位量是常量 / 常量折出来 | 常量 → 换成 0..31；变量 → `x & 31` |
| `UB-OOB` | 数组、堆块常量下标越界 | 下标能折成常量，且落在 `0..n-1` 外 | 换成合法下标；确实要这个下标就把数组声明改大（给 `int a[5];`） |
| `UB-NULL` | 解引用空指针 | 指针是 `NULL` / 赋过 0 的字面量 | `if (!p) { … return …; }` 守卫 |
| `UB-UAF` | `free` 之后再读/再写 | 同函数内直线追到 `VS_FREED` | 把 `free` 挪到作用域末尾（`defer free(p);`）或删掉这次使用 |
| `UB-DFREE` | 同一指针 `free` 两次 | 第二次 `free` 前状态已是 `VS_FREED`（含 `defer free` + `free` 撞车） | 删掉重复的那次 `free`；或释放后立刻 `p = NULL;` |
| `UB-ESCAPE` | `return &局部变量`、`return 局部数组` | 返回表达式直接取局部地址 | 改成调用方传缓冲区进来（给函数签名），或按值返回 |
| `UB-UNINIT` | 读 `malloc` 出来没写过的内存 | 堆块状态是 `VS_HEAP`（没写过） | 先写一遍，或把 `malloc` 换成 `calloc`（给整行） |
| `UB-VLA` | 零长度数组 | 长度常量折成 0 | 长度改成 ≥ 1 的常量 |
| `UB-OVERLAP` | `memcpy` 源与目标重叠 | 两个实参是同一个对象（同名标识符） | 换成 `memmove` |
| `UB-NULLARG` | `memcpy`/`memset` 等传常量 0 指针 | 实参是字面量 0/`NULL`，且该位置必须非空 | 传真实缓冲区，或加空指针守卫 |

## 4. 「一定」与「可能」的口径

* **一定（`CONF_CERTAIN`）**：不依赖运行时就能定死。常量折叠出来的结果、
  沿直线代码追出来的指针状态、同一表达式里看得到的同一对象。
* **可能（`CONF_POSSIBLE`）**：要合上调用约定、别名或运行时才知道。例如对
  `malloc` 出来的内存的读（可能别处已经写过）、非字面量下标的越界。

口径固定下来是为了**让报告可用**：每条「一定」都应该能当场改掉，每条「可能」
都应该经得起「你凭什么这么说」的追问。所以宁可降级，也不硬报——更不会报
「可能有风险」这种说不出改法的东西（说不出具体改法的发现直接不生成）。

`UbOpts.quiet_uncertain` 非 0 时只留「一定」级。

## 5. 抑制：`c6ub-ignore`

在**出问题的行**上（或紧挨着的上一行）写注释：

```c
int a[4] = { 0 };
return a[4];   /// c6ub-ignore UB-OOB
```

* `c6ub-ignore`：这一行的**所有**发现都跳过。
* `c6ub-ignore UB-OOB`：只跳过这一个检查，同行的别的发现照报。
* 被压掉的条数在 `ub_suppressed()` 里，CLI 会在汇总行里说「压掉 N 条」——
  **抑制不等于消失**，它只是被计数。

用它的场合就两个：故意的边界代码（比如自己实现的内存池在末尾多留一格），
以及检查器的已知误报。别拿它当「先关掉再说」。

## 6. 三件套的 API（自己写工具时）

```c
import std.analysis.lex;
import std.analysis.parse;
import std.analysis.ub;

Arena a = arena_make(1 << 20);

/* 1) 词法：Lexer 是**纯值**，结构体赋值就是快照，回滚直接 *self = save */
Lexer lx = lx_open(S("int main(void) { return 0; }"));
for (Token t = lx_next(&lx); t.kind != TK_EOF; t = lx_next(&lx))
    printf("%d:%d %.*s\n", t.line, t.col, (int)t.text.s.len, t.text.s.ptr);

/* 2) 语法：AST 全放调用方的 Arena，Program 里是函数表/符号表/错误账 */
Program *p = parse_program(&a, src);
printf("nerr=%d nfunc=%d nstmt=%d\n", parse_errors(p), p->nfunc, p->nstmt);

/* 3) UB 检查：先设 Program，再跑 */
UbOpts o = ub_opts_default();
Ub *u = ub_open(&a, S("x.c6"), src, o);
ub_set_program(u, p);
ub_run(u);
for (Finding *f = ub_findings(u); f; f = f->next)
    printf("%s:%d:%d: %s [%s] %s\n", f->file.s.ptr, f->line, f->col,
           ub_conf_name(f->conf), ub_check_name(f->check), f->msg.s.ptr);
```

要点：

* `parse_program` **不抛错、不中断**：不认识的构造记进 `Program.nerr`，并把前
  32 处 `(line,col)` 留在 `Program.errl/errc` 里。用
  `ub_not_analyzed()` 拿到「没看懂几处」，自己决定是警告还是拒绝出报告。
* `Lexer` 里没有堆分配，`lx_peek(&lx, n)` 只读不前进；`lx_open` 保的是**调用方
  的切片**，源码得活到分析结束。
* 所有 `Str`/`Token`/`Node` 都是指向**原源码或 Arena** 的视图，没有拷贝、没有
  二次分配；一个 100 KB 的文件跑完不留垃圾。

## 7. 限制（诚实清单）

这些是**设计上就不做**的，不是「以后再说」：

1. **不跨函数**：只看单个函数体。`f()` 里 `free(p)` 之后 `g()` 里用 `p`，
   查不出来。
2. **不做别名分析**：`int *q = p; free(p); *q = 1;` 里的 `*q` 不认。
3. **不认 `realloc` 之后的旧指针**：`realloc` 按「新分配」处理。
4. **堆块大小只认常量长度**：`malloc(n)` 时 `n` 不是常量就只记「未知大小」，
   越界检查跳过（不会猜成 0）。
5. **不展开宏、预处理和 `#include`**：看的是文本层面能认出来的 c6 构造；宏生成
   的代码不在视野里。
6. **类型模型是简化的**：`int` 按 32 位、指针按 8 字节、`i64`/`u64` 按 8 字节；
   不对齐/严格别名（strict aliasing）这两类 UB **不查**。
7. **`switch` 穿透、无限循环、`goto` 跨作用域**这些控制流细节按直线代码近似：
   分支汇合处的变量状态取「两边一样才算已知」，否则降级成「未知」。
8. **解析器不认的构造一律不猜**：内联汇编里带冒号的 `__asm__(… : … : …)`、
   部分 freestanding 例子里的方言，会走「没认出来」这条路，并在报告里点名——
   `std/` 下全部 `.c6` 与绝大多数 `examples/*.c6` 都能被完整解析（`nerr = 0`）。

## 8. 回归

```sh
make std-ub      # 编译并跑 examples/stdub.c6（演示 9 条：一定 8、可能 1）
make stdtest     # lex 6 / parse 47 / ub 63 条用例，全绿
```

`std/analysis/ub.c6` 自己的用例覆盖了每类检查的正例和反例，也包括「只报一遍」
「干净的程序一条都不报」「`c6ub-ignore` 能压一行、也能只压一个检查」这些
容易写歪的行为。
